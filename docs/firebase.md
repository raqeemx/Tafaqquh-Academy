# ربط Firebase — مشروع tafaqquh-academy

## ما أُعدّ

- Firebase Web SDK للمصادقة بالبريد وكلمة المرور، وإرسال التحقق واستعادة كلمة المرور.
- بيانات تطبيق الويب التي وفرها صاحب المشروع محفوظة محليًا في `.env.local` فقط. ملف `.env.example` يوضح الأسماء المطلوبة؛ لا يحتوي قيم تطبيق الويب الفعلية سوى معرّف المشروع المعلن.
- الجلسة في `browserSessionPersistence`؛ لا يكتب التطبيق كلمات مرور أو رموز هوية في السجلات أو ملفات المشروع.
- تسجيل الحساب ثم إنشاء `students/{uid}` بحالة `pending`. إذا نجح Auth وفشل Firestore تظهر استعادة الطلب في `/student` دون إنشاء حساب جديد أو تغيير قرار سابق.
- المحتوى محمي بشرطين معًا: بريد موثّق وحالة حالية `approved`. الحالات `pending` و`rejected` و`suspended` والملف المفقود ممنوعة.
- `/student` غلاف واجهة عام لا يتضمن بيانات مقيدة في HTML. جلب المحتوى عبر `/api/student/content` يتحقق من ID token وإبطاله وتعطيل الحساب وحالة القبول الحالية، ويعيد `Cache-Control: private, no-store`.
- Admin SDK مع `server-only` وتهيئة كسولة وApplication Default Credentials. لا تحتاج صفحات الموقع العامة إلى بيانات Admin كي تُبنى.

## إعدادات Console المطلوبة قبل التفعيل

1. افتح مشروع **tafaqquh-academy** الموجود. لا تنشئ مشروعًا جديدًا.
2. Authentication → Sign-in method: فعّل **Email/Password**. اضبط سياسة كلمة المرور (ثمانية أحرف على الأقل، ويمكن تشديدها)، وفعّل حماية تعداد البريد إن كانت متاحة. راجع قوالب التحقق واستعادة كلمة المرور بالعربية.
3. Authentication → Settings → Authorized domains: `localhost` موجود بالفعل وفق طلب قراءة ناجح. أضف اسم نطاق التطبيق النهائي فقط عند الحاجة. استخدم `http://localhost:3000` محليًا.
4. Firestore Database: إذا لم توجد قاعدة `(default)`، أنشئها بوضع Production واختر الموقع المناسب قبل الإنشاء؛ تغيير الموقع لاحقًا غير مباشر. لا تستخدم Test mode المفتوح.
5. راجع وانشر محتوى `firestore.rules` في تبويب Rules قبل فتح التسجيل. هذا تطبيق قواعد أمان للمشروع، وليس نشر التطبيق؛ **لم ننفذه تلقائيًا** لعدم توفر وصول إداري موثوق إلى Console/CLI. يمكن للمشغّل لاحقًا استخدام `firebase deploy --only firestore:rules,firestore:indexes --project tafaqquh-academy` بعد تسجيل الدخول ومراجعة القواعد.
6. لا حاجة لتفعيل Cloud Storage أو الفوترة الآن. `storage.rules` تمنع كل وصول كإعداد مبدئي، ولا تُستخدم ملفات أو تسجيلات. إذا كانت لديك ملفات أو قواعد قائمة، راجع أثر أي استبدال قبل تطبيقها.
7. بعد الخطوات السابقة اجعل `NEXT_PUBLIC_FIREBASE_AUTH_ENABLED=true` في `.env.local` وأعد تشغيل dev؛ في بناء الإنتاج يجب إعادة البناء لأن `NEXT_PUBLIC_*` تُضمّن وقت البناء. هذا المفتاح لتعطيل الواجهة أثناء الإعداد، **وليس بديلًا عن القواعد**.
8. اعتمد سياسة الخصوصية والموافقة على جمع الاسم والبريد قبل إتاحة التسجيل للجمهور.

القيم العامة مثل apiKey ومعرّف التطبيق ليست مفاتيح Admin، لكنها محفوظة محليًا لتجنب نشر إعداداتك بلا حاجة. `.env.local` وملفات الحسابات المعروفة و`.pem` و`.key` مستثناة من Git. لا تضع أي مفتاح خاص في `NEXT_PUBLIC_*`.

## نموذج البيانات وحدود الصلاحيات

| المسار                   | القراءة                                             | الكتابة                                                                                           |
| ------------------------ | --------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `students/{uid}`         | الطالب صاحب UID فقط، دون list                       | إنشاء ذاتي مرة واحدة بحالة pending وحقول محددة وتوقيت الخادم؛ التحديث والحذف للخلفية الموثوقة فقط |
| `restrictedContent/{id}` | طالب مقبول وبريده موثّق؛ المستند published=true فقط | خلفية موثوقة فقط                                                                                  |
| `admissionAudit/{id}`    | لا قراءة من العميل                                  | خلفية موثوقة فقط                                                                                  |
| أي مسار آخر              | ممنوع                                               | ممنوع                                                                                             |

مستند الطالب: `uid`, `email`, `displayName`, `status`, `createdAt`, `updatedAt`. لا يوجد دور يمكن للطالب تعيينه، ولا يستطيع تغيير حالة طلبه أو حذف طلب مرفوض وإعادة إنشائه. لا تسمح القواعد حتى لحساب يحمل claim باسم admin بالكتابة؛ الإدارة هنا عبر ADC/Console الموثوق فقط.

المحتوى المبدئي: `title` و`body` كنص عادي و`published` كقيمة منطقية. الاستعلام الخلفي محدود بـ50 مستندًا منشورًا. لا توجد مواد حقيقية أو تجريبية مزروعة في المشروع الحي. لا تضع مواد مقيدة في `public/` أو روابط تنزيل عامة؛ البيانات المحمّلة سابقًا إلى المستخدم لا يمكن سحبها من ذاكرته، لكن تعليق الحساب يمنع الطلبات التالية.

## تجهيز Admin محليًا

اجعل `FIREBASE_PROJECT_ID=tafaqquh-academy` و`FIREBASE_ADMIN_ENABLED=true` فقط بعد توفير ADC صحيح. يفضّل حساب خدمة منفصل بصلاحيات أقل ما يلزم: تحقق Auth/قراءة المستخدم وقراءة Firestore لخادم المحتوى؛ حساب المشغّل الذي يعتمد الطلبات يحتاج كتابة Firestore أيضًا. لا تستخدم Owner لخادم التطبيق.

داخل بيئة Google المدعومة تستخدم هوية الخدمة المرفقة، فلا حاجة إلى ملف مفتاح. محليًا، إن كانت سياسة المشروع تسمح بملف حساب خدمة، احتفظ به **خارج المستودع** واضبط `GOOGLE_APPLICATION_CREDENTIALS` لمساره فقط. لا ترسل الملف في المحادثة ولا تضفه إلى GitHub. بيانات اعتماد `gcloud auth application-default login` العادية لها قيود مع Firebase Auth؛ اتبع توثيق Admin الرسمي أو استخدم هوية خدمة مناسبة.

إبقاء Admin غير مفعّل لا يمنع التسجيل بعد تفعيل Web SDK والقواعد؛ لكنه يجعل endpoint المحتوى يعيد 503. لا توجد جلسة خادم بالكوكيز في هذه المرحلة؛ كل طلب للمحتوى يحمل Bearer ID token ويُتحقق منه على الخادم.

## قبول الطلبات

أداة مشغّل محلية، وليست صفحة إدارة مفتوحة أو endpoint:

```powershell
$env:FIREBASE_PROJECT_ID='tafaqquh-academy'
node scripts/set-admission.mjs USER_UID approved
# الأمر أعلاه معاينة فقط، دون اتصال. عند التفويض الفعلي:
node scripts/set-admission.mjs USER_UID approved --apply
```

القيم المسموحة: `approved`, `rejected`, `suspended`. الأداة تتحقق من وجود المستخدم والطلب ومن البريد الموثق والحساب غير المعطل قبل القبول، ثم تحدّث الطلب وتسجل الحدث في transaction واحدة. لا تُنفَّذ أداة القبول في المتصفح. راجع Cloud Audit Logs لتتبع هوية المشغّل. لم تُجرَ أي موافقة على مشروعك الحي.

## الاختبار المحلي دون بيانات حقيقية

المتطلبات: Node.js 22 وJava 21 أو أحدث، وChromium للاختبارات.

```sh
npm ci
npx playwright install chromium
npm run test:rules
npm run lint
npm run typecheck
npm run build
npm test
```

`test:rules` يشغّل Auth وFirestore على loopback فقط وبنفس معرّف المشروع، دون إنشاء مشروع Firebase أو حساب حي. لا يشغّل أي خدمة أخرى. الاختبارات تتحقق من عناوين المحاكيات قبل العمل. الاختبار التكاملي يشغّل Next dev على 3100 ويضبط إعدادات وهمية محلية صراحةً، ويحظر طلبات المتصفح خارج localhost. المحاكي يمسح بياناته المحلية؛ لا تشغّل الاختبار على جلسة محاكاة تريد الاحتفاظ ببياناتها.

اختبارات Playwright العادية (`npm test`) تفترض أن التسجيل غير مفعّل في بناء الاختبار (`NEXT_PUBLIC_FIREBASE_AUTH_ENABLED=false`). تغطي توقف الخدمة الآمن، المسارات العربية، ورفض API المجهول. استخدم `PLAYWRIGHT_CHANNEL=chrome` لتشغيل Chrome المثبت بدل Chromium إن أردت.

إعدادات المحاكيات اليدوية: `NEXT_PUBLIC_FIREBASE_USE_EMULATORS=true`, `FIREBASE_USE_EMULATORS=true`, `FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:9099`, `FIRESTORE_EMULATOR_HOST=127.0.0.1:8080`. لا تترك متغيرات emulator مضبوطة مع مشروع حي. Admin يرفضها في production؛ استخدم `npm run dev` للاختبار التكاملي المحلي.

## ما لم يُختبر حيًا

تمت قراءة إعدادات Auth العامة بنجاح والتحقق من النطاقات المصرّح بها. لم تُنشأ حسابات حقيقية، ولم تُرسل رسائل بريد حقيقية، ولم تُكتب مستندات أو تُنشر قواعد أو تطبيق. لا تثبت قراءة الإعدادات تفعيل Email/Password أو وجود قاعدة Firestore أو صحة القواعد الحالية؛ يلزم إكمال القائمة أعلاه. لا تفعّل الفوترة أو أي خدمة مدفوعة ضمن هذه المرحلة.

المراجع: [Auth بالبريد](https://firebase.google.com/docs/auth/web/password-auth)، [قواعد Firestore](https://firebase.google.com/docs/firestore/security/rules-conditions)، [تهيئة Admin](https://firebase.google.com/docs/admin/setup)، [اختبار القواعد](https://firebase.google.com/docs/rules/unit-tests).

## تنبيهات أدوات التطوير

تدقيق اعتماديات التشغيل (`npm audit --omit=dev`) بلا ثغرات معلنة وقت الاختبار. بقيت خمسة تنبيهات متوسطة في شجرة أدوات Firebase CLI التطويرية (`@opentelemetry/core` و`uuid` واعتماداتهما). طُبقت الإصلاحات غير الكاسرة المتاحة؛ لم نستخدم `audit fix --force` لأنه يقترح رجوعًا رئيسيًا لـfirebase-tools. هذه الأدوات لا تدخل حزمة تطبيق المتصفح، ويجب متابعة تحديثها قبل تشغيل أدوات إدارة على مصادر غير موثوقة.
