# إدارة المحتوى التعليمي

المسار `/admin/content` يضيف البرامج والمواد والكتب والسلاسل والدروس، ويعدل العنوان والوصف وترتيب العرض وتاريخ الدرس وحالة النشر. البداية برنامج ثم مادة، ثم كتاب اختياري، ثم سلسلة ثم دروس. لا توجد بيانات أو أسماء منسوبة للشيخ مزروعة في الخدمة الحية. خانة «منشور» غير محددة في السجل الجديد. إلغاء تحديدها يخفي السجل دون حذفه؛ مكتبة الطالب تتحقق من نشر البرنامج وجميع التصنيفات الأب.

`programs` يحافظ على النموذج السابق. `catalog` يحمل kind وprogramId وparentId والعنوان والوصف والترتيب وتاريخ الدرس وحالة النشر. لا يكتب الطالب هذه المجموعات. كل تعديل يمر بـAdmin SDK ويتحقق من الدور الحي داخل معاملة مع سجل التدقيق، ويمنع الكتابة فوق تحديث أحدث بواسطة version. لا يغير التعديل نوع السجل أو برنامجه حتى لا تصبح الدروس التابعة يتيمة؛ يمكن تغيير التصنيف الأب المتوافق داخل البرنامج. التاريخ يوم تقويمي دون تحويل منطقة زمنية.

من صفحة الطلبة يمكن منح وسحب البرامج كما سبق. قسم إعدادات العرض داخل إدارة المحتوى يحفظ منطقة زمنية IANA مثل Asia/Baghdad أو UTC ويستخدمها سجل الطلبات والتدقيق؛ أعد فتح اللوحة بعد تغييرها. الإعداد الافتراضي بغداد.

البحث والتصفية والترتيب في قائمة الإدارة على الفهرس المحمل؛ API يقرأ صفحات 100 سجل. يمكن توسيع البحث الخادمي لاحقًا عندما يصبح حجم الفهرس كبيرًا. النشر لا يرفع ملفات Drive ولا ينشئ روابط عامة.

## منع النشر غير المقصود

المشروع الافتراضي في `.firebaserc` هو demo-tafaqquh. أوامر deploy في npm وpredeploy لقواعد Firestore وفهارسه وStorage تفشل عمدًا، وبناء بيئة غير local محظور. لا توجد وظيفة نشر في Actions. ملفات الاستضافة السابقة محفوظة، لكن تشغيل نشر مستقبلي يحتاج تغييرًا مراجعًا منفصلًا وموافقة صريحة. هذه حواجز لمنع الخطأ، وليست بديلًا عن IAM؛ مالك المشروع يستطيع تجاوز ملف الإعداد أو النشر من Console. لا تختبر الحماية بتنفيذ أمر نشر حي.

فحص Gitleaks في GitHub Actions يفحص الأسرار عند push وpull_request بتاريخ Git كامل، بصلاحية قراءة ودون تعليق تلقائي. لا ترسل اعتماد Drive أو حساب خدمة في المحادثة أو المستودع. لم تُنشأ بيئة Staging أو خطة نشر جديدة.
